## 0. 现状（写 Spec 时核对过，main @ 0a0cb64）

- 信源都写在仓库根目录 `sources.json` 的 `sources` 数组里。三种 `type`：`telegram`（13 个 TG 频道）、`inbox`（5 份每天生成的期刊：邮件精华、环球要闻、推特爆款、GitHub 热门、今日重点）、`feed`（RSS/Atom，代码已支持，`shiguang/ingest/web.py`，但**现在一个 feed 源都没配**）。
- 校验和默认值在 `shiguang/config.py` 的 `prepare()`；`visibility` 只有 `public` / `private`。
- TG 帖子和 feed 条目都存在 `tg.db`（feed 在 `entry` 表），图片缓存在 `media/<source>/`。
- 话题分组 `topics` 是 `sources.json` 里的正则列表（全球、财经、AI、科技、数码、汽车、开发者、社会、娱乐）。
- **注意**：`shiguang/site/history.py` 第 12–14 行有一个写死的 `ALLOWED` 来源白名单（公开历史归档用），里面也有 pelosi3、liangjiahepost、titan_pain。
- 要停的 3 个源在 `sources.json` 里的 id：`pelosi3`（敏感经济信息分享）、`liangjiahepost`（梁家河邮报）、`titan_pain`（某科学的一个频道）。

## 1. 停掉 3 个源

1. 从 `sources.json` 的 `sources` 数组里删掉 id 为 `pelosi3`、`liangjiahepost`、`titan_pain` 的三项。删了以后采集器就不会再抓这三个频道。
2. **历史数据全部保留**：不删 `tg.db` 里这三个频道的消息，不删 `media/` 里的图，不改 `public-feeds/` 里已经生成的旧日期文件。
3. `history.py` 的 `ALLOWED` 白名单**保留**这三个 id，保证旧日期的历史归档页面还能正常显示它们以前的条目。在白名单旁加一行注释：「已停用来源，只为旧归档保留」。
4. 停用后，新一天的首页、话题页、「按渠道」里不再出现这三个源的入口；旧日期归档里照常显示。

## 3. 试跑数据怎么存、怎么数

**目标**：8 个源每小时照常抓，但**任何页面都看不到**（公开站、私有站、首页、话题页、按渠道、历史归档、`public-feeds/` 全不出现），跑一周看量。

1. 新建仓库根目录文件 `trial-sources.json`，8 个试跑源写在这里，**不写进 `sources.json`**。这样现有页面生成代码天然拿不到它们。
2. 每个试跑源的字段：`id`、`name`、`section`（`好玩` 或 `好买`）、`category`（引用第 4 节的分类 id）、`fetch`（`rss` / `page`）、`url`，网页源再加 `parser`（`ucca` 或 `douban_events`）。
3. 抓到的条目存进 `tg.db` 里**新的一张表** `trial_item`：`source_id`、`section`、`category`、`url`（唯一键，去重用）、`title`、`summary`（截 500 字）、`image_url`（有就存地址，不下载图片）、`published_at`、`fetched_at`（UTC）。网页源抓不到发布时间就留空。
4. 不下载图片、不写 `media/`、不写 `public-feeds/`。
5. **每日数量报告**：新增命令 `python tools/trial_report.py [--days 7]`，读 `trial_item`，按北京时间日期输出一张表：日期 × 源 的新增条数，再加按 `section`、按 `category` 的小计，以及每个源最近一次成功抓取时间。输出到终端，同时写 `reports/trial/YYYY-MM-DD.md`（`reports/` 加进 `.gitignore`，不提交、不发布）。
6. 一周后（约 10/29）由产品 bot 拿报告看量，再决定好玩/好买怎么设计。

## 4. 分类由数据决定，不写死

1. `trial-sources.json` 顶层放一个 `categories` 数组，每项 `{id, name, section}`，例如 `stargazing / 观星 / 好玩`、`shows / 影视 / 好玩`、`games / 游戏 / 好玩`、`exhibitions / 看展活动 / 好玩`、`apple / 苹果数码 / 好买`、`3d-printing / 3D 打印 / 好买`。
2. **上限**：每个 section 最多 8 个分类，总共最多 16 个。超过上限、id 重复、源引用了不存在的分类，加载时直接报错退出（和现有 `prepare()` 的写法一致）。
3. 代码里不能出现写死的分类名或分类数量；加一个分类只改 `trial-sources.json`。
