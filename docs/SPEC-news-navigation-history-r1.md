## 1. 结论

页面只保留 **速览、热点两个视图**。**栏目并入来源**，不再作为第三种平行视图；**主题是内容筛选**，日期是这次浏览的时间范围。所有入口引用同一批稳定条目与来源身份，不复制内容表或重复生成卡片。

| 维度 | 回答的问题 | 建议呈现 |
| --- | --- | --- |
| 日期 | 看哪一天？ | 日期选择、今天快捷入口；历史状态明确显示日期 |
| 视图 | 怎么看？ | 速览按条目时间看全部；热点按已确认事件规则看重要事件 |
| 主题 | 内容讲什么？ | 全部、国际、财经、科技、汽车、社会、娱乐；科技包含原AI/科技/数码/开发者 |
| 来源 | 从哪里看到的？ | 一个来源选择器，包含普通资讯来源和原栏目来源；选中后可读其原文/完整期刊 |
| 搜索 | 在这个范围内找什么？ | 只搜索当前日期、视图与筛选范围；清楚标“搜索这一天的资讯” |
| 采集渠道 | 用什么方式接入？ | TG、RSS、网页、inbox 属于内部适配信息，不再增加用户筛选层 |

同一条报道既可从速览找到，也可从其来源入口找到，这是同一记录的不同入口；重复指同一结果列表里重复出现同一条，而不是禁止跨入口访问。

## 2. 两个视图与来源入口

### 速览

覆盖选定日期内全部合格资讯，包括原期刊/栏目条目；仍按 #12 D3 的条目发表时间优先归日，不把整期所有旧稿改成期刊当天的新消息。仅日期记录保留精度。同日头条只置顶一次，正文排除同一UID；连续同源折叠、搜索命中展开、按单来源不折叠规则沿用。

### 热点

是新闻事件聚合视图，不是速览的另一份手写清单。不改 #12 已确认的候选资格、规范来源去重、评分、12小时合并窗口或按小时排序。X、GitHub及不符合热点资格的策展内容仍不加入候选。

主题/来源/关键词筛选作用于已计算事件，不能因用户选择一个来源就按筛选后的成员重算事件分数。一个事件在同一日期结果中只显示一次，可展开看成员报道与出处；“N个频道”改用更明确的“N个来源报道”，数字仍按规范来源身份计数，不改统计口径。

主题按事件代表条目的既有主题匹配；来源命中任一成员即匹配该事件；关键词检索代表与成员标题/摘要，命中后仍只显示一张事件卡，展开标明匹配报道。尚不具备成员数据时不能假装支持这些条件，接入阶段须补齐或明确该项不可用。选中X/GitHub等不参与热点的来源时，给出原因及“切到速览/清除来源”动作，不悄悄替换为全部来源。

### 栏目并入来源

“GitHub热门”“环球要闻”“推特爆款”等保留来源身份、别名和历史入口，纳入同一个来源选择器；需要区分时用选择器分组“资讯来源/栏目来源”，不再做第三个Tab或在速览底部复制三组卡片。

选定期刊来源后显示其当日条目，并保留“阅读完整期刊”入口。普通原文链接指向条目原文；完整期刊链接指向该期，不相互冒充。栏目名称“环球要闻”不等于主题“国际”：国际也有其他来源，环球要闻也可含不同主题。

归档页、来源页、原栏目URL不直接删除。正式整合时核对并保留兼容入口；#14原型先保留内部 `look` 路由和条目/收藏ID。

## 4. 日期选择与历史查询

- 日期只控制资讯；“今日”首页仍指北京时间今天，收藏仍按收藏时间管理。离开资讯再返回保留其日期与筛选状态。
- 日期选择是现有“时光机”的统一入口，不再新增另一个“历史”Tab。浏览的是当前存档中归属于该日期的内容，不承诺重放当时看到的页面快照；后来补齐的内容仍保留原发表时间。
- 标题附近常驻日期选择和“今天”入口。日期弹层内提供日历以及上一/下一有存档日的操作，44px点按区；跨过缺失日时明确是“上一/下一存档日”，不冒充自然日连续档案。窄屏不靠缩字/缩触控区塞下控件。
- 日期清单由**当前公开/内网范围内真实可浏览的存档清单**生成，不能从私有数据推导公开日期或计数。未来日期不可选；今日即使尚无内容，也有明确空态。
- 速览按真实存档列可用日期，不承诺“全部历史”“固定14天”或无限回溯；图片14天保留不等于新闻只保存14天。未留存的日期说明“该日没有可用存档”，不使用当天数据替代。
- 热点沿用已确认的最近3个自然日边界；日内确实没有事件与未保留热点存档是两个状态。选择更早的历史日期时仍保留用户选择，显示“该日期的热点未保留，可查看当日速览”，由用户点击切换，不暗中换日期/视图。扩展热点历史保存期另案批准。
- 切换日期保留视图、关键词及仍可识别的主题/来源。某条件在该日没有结果时给“清除筛选”或“查看其他日期”，不静默清空条件、回到今日或混入其他日期内容。日期可用性依据基础存档，不能因当前关键词无结果就把日历日期伪装成未存档。
- 时间使用 Asia/Shanghai，沿用条目时间优先、仅日期精度及事件首次报道归日规则，不以采集时间冒充发表时间。期刊归日/链接与条目归日可不同，分别保留。
- 日期、view、topic、细分topic、source、q写入可复现URL；刷新、浏览器前进/后退、分享本地评审链接应恢复同一状态。Playground保留focus参数与 `#screens/look`；正式页面地址在整合阶段按实际路由兼容，不新增未经讨论的服务端API。

## 6. 验收场景

- 同一日期速览/热点有各自视图语义，栏目条目在速览按原时间混排；同一列表没有重复UID，期刊完整入口仍在。
- 科技一级能找到AI、数码、开发者及科技记录；细分能缩回原范围，旧主题链接不丢语义；来源筛选与内容主题独立。
- 选择确有存档的历史日期，只显示该日内容；日期/来源/主题/关键词组合及URL刷新、前进后退一致。
- 只有日期的条目不出现伪造时刻；跨日事件遵守原首次报道规则；未来、缺失档案、当天空结果各有正确状态。
- 最近3日内无热点与超出保留期可区分；不拿今天热点伪装历史，不因选来源而改变事件总分。
- 公开日历、计数、来源选择和搜索结果均不泄露私有来源；收藏ID与既有链接保持兼容。
- 日期/来源/搜索/Tab可用键盘，控件至少44px；手机亮暗、密度及320窄屏无溢出，日期弹层有焦点管理与关闭返回。
