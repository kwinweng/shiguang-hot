## 3. 资讯时间流与数据合同

### 3.1 排序、归日与身份

1. 使用 Asia/Shanghai。沿用 D3：条目原始发表时刻优先，其次有明确依据的期刊发表时刻，再次仅日期；保存时间依据及精度，不以采集/补录时刻替代，不伪造00:00、23:59或缺失时区。资料不足时保留仅日期精度。
2. 有精确时刻的条目按归一化后的发表时刻从新到旧；同日仅日期记录放在该日精确时刻记录之后，标“仅日期”。日期之间从新到旧衔接。验收分别检查精确时刻子序列和仅日期规则，不将“仅日期”偷偷变成数值零点参与验收。
3. 同时刻沿用总 Spec 的稳定顺序：规范来源 `order` 升序，数字 `native_id` 按数值倒序，再以稳定 UID 兜底。保留原始时间字符串及旧收藏身份；改排序/展示日期不得重算 ID。
4. 不用热度、来源权重或轮转打破时序，不把头条、昨日摘要、整期摘要重复插到资讯流首位/中间。期刊条目按自己的有效发表时间进入同一流，完整期刊入口另列，不把期刊日期强加给全部旧稿。
5. 跨页、自动续载、手动跳日和缓存命中均按 UID 去重；同一来源别名/同一期副本不得重复卡片。不同来源对同一事件的独立报道仍在速览中各自保留，热点的事件归并逻辑不变。
6. r1 连续同源局部折叠规则保留：原顺序前三条后原位开合，单来源不折叠，搜索命中可达，清空后恢复开合状态；**它不是全局条数上限或加载开关**。自动续载不得等待用户点击局部折叠。若完整 v4 规范另有要求，须明确列出差异后再审，不直接猜改。

### 3.2 两视图、主题与来源

- 资讯仍只保留速览/热点。全部、国际（全球/环球别名）、财经、科技、汽车、社会、娱乐为一级；科技保留 AI/科技/数码/开发者细分。未知条目从全部可达，旧主题/来源链接保留原范围。
- 来源、一级主题、科技细分取交集，不能从来源名称推断条目主题。GitHub热门、环球要闻、推特爆款纳入同一来源选择器；原文与完整期刊链接不混用。TG/RSS/Web等接入方式不增加菜单层。
- 热点延续 r1 的事件查询：主题匹配代表，来源命中任一成员，关键词检索代表和成员；条件不改变已计算分数与规范来源数。选中不参与热点的来源给解释及切速览/仅清除来源，不静默放宽。
- **Q19-3=A，已解决**：搜索只查当前已加载的日期；续载新日后将该日纳入同一关键词过滤。界面明确“仅搜索已加载日期”，未加载日不得标作搜索无结果；不新增全历史全文索引，不为搜索预取全部历史。来源/主题日期索引仍覆盖真实公开存档；关键词仅在已加载日参与匹配，日历/胶囊不能声称已检索未加载日。

## 4. 连续加载、筛选与日期联动

### 4.1 已定目标及拟议加载合同

- 首次进入从选定日开始；默认定位北京时间今天。**按天分批加载已定**：当日末尾进入加载区后自动请求更早的有匹配存档日，直到最早可读日，结束时明确“已到最早存档”。没有日级跳转的404探测循环，也不一次预载全部历史。
- 手动日历/胶囊选日直接加载该日，不要求先顺序读完中间日期。请求完成后把该日第一条匹配报道放到列表首个可阅读位置；日期标识必须和该条归属日一致。加载中标目标日期；失败保留原内容和阅读位置，不用其他日顶替。
- 遇缺失日期跳到下一**有匹配内容的存档日**，界面使用“上一/下一匹配存档日”，不假装自然日连续。基础存档为空/当前筛选无匹配时不生成可拖落的假日期；深链接主动指向这些日期时保留日期与条件并说明原因，提供改日期/清筛选动作，不悄悄跳走。
- 切来源/主题/细分后使旧请求和旧游标失效；结果、日期索引及胶囊使用同一查询快照。返回较晚的旧请求不可混入新条件。缓存至少按可见范围、存档版本、日期、来源/主题/细分及确认后的搜索范围区分。
- 稳定游标和 UID 去重避免重复载入；请求失败停止自动重试连环触发，给原位重试。没有额外日期/滚动第三方库；浏览器原生滚动、Pointer Events及必要的观察机制即可。
- 不设用户可达历史的总条数上限。可以回收离视窗很远的 DOM/内存，并按日恢复，但不能以此截断可访问历史或丢失阅读位置；实现方案另在开发批准后验证。

### 4.2 日历和胶囊共用筛选日期索引

1. 一个公开/内网各自独立的基础存档清单；公开清单只能从已批准公开来源生成。最早日期是**该范围真实留存**的最早日，不从私有输入、客户端时钟或固定天数猜测。
2. 来源×主题×细分必须有准确的联合匹配依据，不能简单取“该日有此来源”与“该日有此主题”的独立计数交集。日历、胶囊和真实列表复用同一过滤谓词/规范别名，跳转日期只来自联合匹配非空的日集合。
3. 基础存档有日、但当前条件无匹配，与缺失/损坏存档分别处理；无可跳转日时禁用胶囊拖动，保留清筛选入口，不能回到全部来源充数。未来日不可选。
4. 索引按天分片/按需读取，客户端筛选针对**已在构建端过滤合格的产物**；不能把私有全文交给浏览器后再隐藏。关键词只查已加载日（§3.2），未加载日仍可按来源/主题选择并加载，加载后才判断关键词命中；不能把尚未检索的历史标成“已确认无结果”。
5. 日历仍是原“时光机”的统一入口，有今天和键盘操作，不增历史Tab。日历与胶囊都提交同一种日期定位动作；热点仍只在其3日存档语义内工作，资讯的长期日期集合不扩大热点保留期。
6. 单源某日被 blocked 或抓取失败，若公开产物无该源当日条目，统一按“该日该源无匹配”处理；日期、来源选择和列表只依据公开产物，不读取或暴露 `fetch_status`、内部错误或采集状态，也不显示异常标记。其他来源的匹配不受影响；这不等同于整日文件缺失/损坏或浏览器加载失败，后者仍保留重试反馈。

### 4.3 URL、返回与其他页面

- 保留 `#screens/look`、focus及既有条目/收藏 ID；正式地址兼容 `index.html`、`archive/<日期>.html` 和既有来源入口，不因换流删掉旧 URL。
- 日期、视图、来源、主题/细分和搜索条件保持可复现 URL；显式选日/改筛选形成可返回的状态，滚动阅读日变化用替换状态或阅读锚点记录，不为每个像素新增历史记录。后退/前进恢复同一查询、锚点条目及合理偏移，不能混日期。
- 胶囊“当前日期”、日期控件及URL锚点取列表第一个真正可阅读条目的归属日；被吸顶筛选完全遮挡的卡片不作为读点。拖动预览日期与已提交阅读日期分开，成功跳转后再同步，防止标题显示新日、列表仍是旧日。
- 收藏仍按收藏时间及原身份管理，不受资讯选日筛掉；离开资讯再用底栏返回保留阅读条件/日期。今日好玩/好买、其他独立功能不因本轮变更被隐式重排。

## 6. 长期历史、按日静态产物与增量构建

### 6.1 保留政策与读取

- 资讯正文、稳定身份、原发表时间/精度、规范来源、主题和既有归档地址长期保留；不按图片14天窗口删正文、日文件或日期索引。最早已有存档清点后记录，新增日继续累积。不能凭本轮 Spec 假称此前所有历史已恢复。
- 图片仍按原14天策略；过期/丢失图使用明确占位或无图布局，标题、日期、原文和收藏仍可用。浏览历史不能自动重抓旧图/原帖来填缺口，也不变更图片生产保留配置。
- 拟采用“按日条目数据 + 日期/联合筛选索引 + 兼容HTML入口”的静态合同，路径例如 `archive/data/<日期>.json`、`archive/manifest.json`；这是待实现的接口草案，本轮不新增数据文件或API。日期数据先按允许来源和可见范围生成，前端只作用户筛选，不担当隐私防线。
- 不一次把全年全文/图片塞进首页或浏览器；按日取数、按需缓存。联合索引只含本可公开的日/规范来源/主题/精度等必要信息，不能把私有日期、计数或来源身份旁路到公开产物。

### 6.2 增量范围、异常日与资产兼容

1. **稳态新增一天**：在已有完整且兼容的归档基线上，无历史输入变化时，只新生成该日归档HTML/日数据；首页、必要的轻量日期索引和原有可变入口单独更新。未变化历史页及日数据内容哈希保持不变，不逐日重新渲染，不以“新增一天”掩盖全量重写。
2. **Q19-5=A，已解决**：今天页面可以更新；旧帖有改动就重建对应归属日，并更新受影响索引，不能按采集日塞到今天，也不冻结历史错误。延迟到达、更正或删除按受影响日期处理。一次性首次建档/旧格式迁移须另行取得阿欢批准，本次决定不授权迁移、回填或恢复采集。
3. 保留现有原子产物切换与公开结构检查。增量不能等于绕过隐私校验；白名单/可见性改变应使相关缓存失效并复核，不能继续公开旧产物。此类更改本轮不授权。
4. 不能删掉未重写历史HTML仍引用的旧哈希CSS/JS，也不能让已过期图片挡住正文。拟按存档引用保留兼容静态资产，或在经批准的迁移阶段统一入口；不可直接沿用当前 `publish_assets(full=True)` 的清理方式。HTML、schema及共享资产版本要有可验证关系，避免旧页引用404。
5. **Q19-6 预答复已采纳**：增量优先复用已发布产物或仓库归档，作为可信历史基线；开发获批后验证现有路径的跨构建复用。若需要修改 workflow、生产配置或新增存储，停止并另案处理，不在 #19 中顺手配置。
6. 不把只减少HTML渲染次数宣称为总构建时间O(1)：当前暂存复制、产物校验、索引序列化和发布传输仍可能随历史体积增加。分别测量并报告，目标是取消无差别历史渲染；其他成本及性能预算交总控初审后由阿欢确定。
7. 620KB/天/约230MB每年只能作为容量假设；需计入HTML、日数据、索引、仍被引用的静态资产及图片，并核验目标平台真实限额、当前占用和余量。达到容量预警时先回报决策，不自动删除历史、换源或迁移部署。长期保留政策不等于在有限存储中承诺无限容量。

### 6.3 正式整合后的回滚

- 整合前留存当前 `rank_home` 加权/轮流取条及热条目置顶版本的代码、完整 HTML 和兼容资产快照，记录实际整合前 SHA。若正式整合后出错，在原审批边界内撤回 #19 的排序、连续加载及增量读取变更，恢复该版本及配套产物，核验旧入口、收藏 ID 和资产引用后再按原发布流程切换；本轮不执行回滚或部署。
