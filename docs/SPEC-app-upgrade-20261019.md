## 4. 信息模型、页面与交互

### 4.1 主类型与兼容

每条记录只有一个主要类型：好看、好玩或好买；话题、发现分组、带狗等标签为独立字段，不复用现有 category 同时承担三种含义。

| 数据 | 规则 |
| --- | --- |
| uid / legacy_id | 新条目生成并持久化稳定标识；旧条目保留既有收藏哈希及原始字段。改类型、标题、显示日期或排序不得重算旧 ID。 |
| source_id / origin_id / canonical_url | 指向规范来源和原始条目；来源别名、跨期副本关联到同一条记录。没有可靠原标识时保留独立记录，不只按相似标题删除。 |
| kind / group / tags | 主类型唯一；好玩四组、好买五组；带狗为跨组标签。未获编辑归类的现有资讯仍为好看，不把所有 GitHub 自动迁成好玩。 |
| published_at / issue_at / precision / collected_at | 区分原始发表、期刊发表、仅日期与采集时间；采集时间不冒充发表时间。 |
| source_visibility / item_visibility | 按更严格者决定可见范围，item不能把private来源变公开。北京本地等个人画像推导内容默认private。 |
| evidence / reason / status | 事实对应原文片段和链接；标记已核实、未核实、传闻或众筹。推荐理由是原文事实的短句重述，不生成虚构体验。 |
| images | 缓存引用、原始URL、来源/署名、宽高、用途（海报/截图/实拍/标识等）；不能把logo称为产品实拍。 |
| event_at / event_until / location | 有明确原文才填；未知不补。失效活动不当作未来活动推荐，但保留归档入口。 |
| official_price | 金额、币种、地区、SKU、官方依据URL及核验时间；无依据为空；只保留最新参考，不建价格序列。 |

现有 TG、RSS、inbox 统一进入 Item；新增来源通过注册和适配进入相同链路，不增加来源专属页面代码。已有公开/内网分离、私有内容结构检查、原子换站与抓取缺口修复保持回归。

GitHub与推特爆款的既有栏目默认继续属于好看。若特定项目经编辑挑为好玩，保留同一uid，主流不再重复出一张好看卡；来源栏目仍能查看该记录，收藏不丢。

不能仅按来源所在表格强行给每篇稿定类型：Eater 的餐厅/目的地可进入好玩的地域组，AKC/Dogster 的养护知识不冒充用品，只有明确用品条目才进入好买·狗狗；Hackaday 的工具玩法与打印设备也分别按条目归类。无法满足任一发现组的普通资讯保留为好看或待审，不新增未经确认的分组。

### 4.2 时间规则、头条与折叠

- 时间均统一为 Asia/Shanghai。按 D3 建议依次采用条目实际发表时间、期刊明确发布时间；都没有时保留仅日期精度，放当日时间流末尾并标“仅日期”。不以采集时间、伪造零点或23:59显示精确时分。
- 相同时间按 sources 的既有 order 升序，再按 native_id 倒序稳定排列；数字 ID 按数值比较，缺失时用稳定 uid 兜底。
- 来源期刊按原期刊日期保持可读，时间流按有效发表时间归日。跨期同源副本使用稳定标识归并；不把不同来源的相似报道从速览里删掉。
- 头条为当天最热事件的代表条目，平局最新；无热点时用最新条目。只置顶一次，正文排除它。今日预览使用同一个头条与正文前3条。
- 连续同源 N>3：保留前3张卡，第4张起原位折叠。摘要为“{来源} 连续 N 条 · 其余 N−3 条”，有展开入口，期刊来源另有完整期刊入口。展开后不重新排序。
- 按来源单选时不折叠；搜索时展开命中成员，清除搜索恢复之前展开状态。无 JavaScript 时仍可手动展开。
- 所有当天合格记录均在对应完整视图可达，预览条数与质量排除各有独立语义，不允许用 home.cap 隐藏正文。

### 4.3 好看与热点

好看三模式沿用关键词搜索、话题、来源和日期归档；筛选状态放在 URL，可刷新复现。没有结果给可清除筛选入口。时光机和今日复用时间流组件。

热点只接受**新闻类型且明确可入热点**的 TG、RSS/feed、world 条目；X、GitHub及好玩/好买策展内容不入候选。新增设计、宠物等 RSS 不因传输格式为RSS就被灌进新闻热点。

评分采用 MRD 主公式：不同规范来源数×4 + 不同关键词命中（封顶3）+ 九话题命中1 + 篇幅分，门槛6，三来源不额外奖励。需取得原70词表后再冻结词边界和同义词口径。

**篇幅精度需一并核对**：旧代码是 min(正文字符数/240, 2)，允许小数；MRD“每240字+1”可能指0/1/2整档。推荐在未取得 UX 原文前保留旧比例算法，只加封顶3的关键词与话题分，不悄悄改变另一项；若原文明确整档则按原文，并重跑量级对照。此项属于算法精度确认，不能用51条的旧估算替代。

- 合并窗口12小时、正文三字片段重合阈值8、标题阈值5；保持原统计预处理，排除原有汇总标题并补周报/月报/盘点。
- 去重事件按不同规范来源计数，每个RSS源/world各1；world内部引用三家媒体仍算world一个来源。不同来源的同一转载稿可以有多个出处，但不按原文罗列媒体数膨胀reach。
- 事件保存成员列表、首次/最近报道时刻及代表条目；代表取最早有效报道，分数取该事件的去重来源数与代表正文，不能把多篇正文拼长来赚篇幅分。
- 热点日归属以首次有效报道的北京时间日期；后续报道增加来源但不复制一张新事件。界面说明“首次报道”，展开能看各成员时刻和出处。
- 按 D4 推荐做日期/小时倒序、小时内热度倒序；保留最近3个自然日。候选计算需要额外12小时上下文，以处理跨日事件，但不把上下文旧事件重复显示。
- 两个已知误合并案例（炼油厂袭击/制裁豁免、IMF离席/市场准入会谈）必须进入回放；仅共享地区、机构和背景词不能作为同一事件依据。若严格v0.5阈值仍误合并，提出可解释的事件区分补充供确认，不能为增加条数默默拆/并。
- 原70词表未到前，不能宣称v0.5热点实现完成；先前自行拟的70词不作为其替代。
- 统计真实候选、事件、入选、误合并、漏合并与各小时数量；自然空小时标0，不编造热点或通过时间改写填格。

### 4.4 好玩、好买

分组顺序固定；胶囊仅列当前日期有内容的组，不显示数量，另有可切换的“带狗”。来源、分类、搜索取交集，切换日期重新计算可用组，不留下指向空组的选中状态。页面全无内容时给回到今日或选择其他日期的操作，不列空组，不写“暂无数据”。

好玩组内：有日期的活动先列仍有效且临近的活动（开始日期升序，进行中标明）；没有活动日期的内容按上新倒序；两类各有“近期可去/新近发现”子标题，避免把“临近度倒序”解释成越远越靠前。无日期时不推断临近度。该排序细化随 Spec 一并确认。

好买组内按上新倒序，大促按开始日期升序；结束节点保留归档但不冒充即将开始。众筹显示文字风险标记，不做倒计时购买诱导。

大图卡主图优先原文成果/实拍/海报；未知或失败用明确占位与原文入口，不拿其他产品图替补。两列高度随图片比例与文案变化，但理由最多2行，完整事实在详情。卡片、收藏按钮和出处操作分别可点，不通过点击收藏误开详情。

好玩详情按类别展示：活动的日期/地点/预约说明，旅行的地点/季节条件，工具/游戏的真实截图和用户主动播放的官方演示，作品的海报/书封与排期。需小程序预约只链官网并提示，不尝试打开或操作账号。

好买详情展示全貌/细节、用途、原文参数、价格依据与来源；价格行无证据则完全省略，不显示“待报价”。官方价带币种地区，原文未指明国行时不得写国行价；禁止币种换算和跨店价格并排。媒体传闻金额如在详情引用须紧邻“传闻”，不进入官方价字段。

好买来源区域保留 MRD 指定边界文案：“来源页含购买链接，我们不下单、不进购物车”。正文无交易按钮；收藏、阅读原文、查看官方依据是主要动作。刷新只覆盖当前事实，既不保存历史价序列，也不生成价格变动提醒。

### 4.5 今日、日报与收藏

- 今日依次好看、好玩、好买；好看头条+3，后两块各4张横滑卡（不足照实显示）。每块底部“看全部 N 条”；N来自该日期、该可见范围内去重后的完整记录数。空块完全省略。
- 日报使用同一聚合查询，覆盖该模式下全部适用来源，而不是另一个手写的来源清单。新来源注册后自然计入来源页、今日、日报及筛选。
- 收藏原样复用三类卡片，按收藏时间倒序混排；类型胶囊只列非空类型，全部常驻。
- 保留现有公开/内网收藏存储隔离。迁移旧记录时不改id、不丢标题/摘要/链接；旧记录缺收藏时间就保留数组相对顺序，不伪造旧时间。类型优先由已知uid索引补齐，无法判定的旧记录兼容按好看显示。
- 新收藏记录带类型、收藏时间和必要快照/图片引用；不维护价格历史，失去新鲜官方依据时不把旧金额作为当前官方价显示。来源到期后仍可读收藏摘要，图失效显示占位，不自动删除收藏。
- 取消收藏原位更新，不强制跳回页顶；临时Toast提供撤销。空态严格用“还没有收藏，点卡片上的书签收藏”。

## 5. 刷新、缓存与失败语义

### 5.1 逐源小时批次

每个规范源记录最近尝试/成功时间、小时批次键、游标与错误状态。按小时到期只抓一次，不因别名、同一源用于两块、多个接口被重复登记而重复整轮抓取。手动及定时完整构建先查到期状态，push 的 NO_FETCH 路径不新抓来源。

同时到期的来源在同一批次内错开请求；同一非公开端点不并发。优先缓存、ETag/Last-Modified和304；必要详情与图仍按源限速，不把“一小时一次”误读成可以无限逐条请求。限流或网络失败按该源退避，不即时频繁重试、不通过另一个实例绕开禁止访问。

单源失败保留其已验证的最近内容和原发布时间，记录源健康，不把抓取时间写成新闻时间；一天没内容不造空组。保留 TG 失败记录和 gap 回填能力。适配器失败由批次层隔离并报告 partial，不静默吞掉；全批次无可用输入或隐私检查失败应阻断发布。Actions成功不能替代“所有来源都新鲜”的验收，源级状态独立列在构建元数据。

生产调度变更受 D1 约束；不会在开发过程中改 cron、bot任务、密钥、域名或部署设置，也不会顺手创建另一套定时任务。上线后每小时同步和监控由既有 bot 承担。

### 5.2 图片与保留

需 Referer、TG 签名地址及短期链接必须在采集侧取得后缓存，浏览器只拿自有缓存地址；不携带用户 cookie。请求的 Referer 只取原来源允许的公开页面，不伪造登录身份。原始URL、署名和对应条目绑定。

初拟沿用14天源图片保留，与当前公开期刊保留口径一致；共用相同资源去重，避免重复存储。生成缩略尺寸与宽高元数据，限制单图下载体积与解码尺寸；用户打开详情才加载大图/演示。来源无图片或抓图失败不随机配图库图，不把 Commons 风景冒充某活动实拍。

图片占位先按真实宽高比预留，骨架/错误状态有文字或可访问名称；减少版面跳动。收藏可能长期留存，14天后源图失效的降级行为按 §4.5，不承诺未实现的永久离线图库。

缓存路径、数据写入必须原子化；下载仅接受公开http(s)资源，拒绝站内私有路径、路径穿越及落到内网地址的重定向，沿用现有安全图片路径处理。

默认/按下/聚焦/禁用/加载/错误全部在组件区可查看；不适用的状态明确说明，例如静态分组标题不伪装“加载按钮”。视觉模拟状态需标“状态示例”，另外提供真实交互进行验证，不能用截图替代焦点或按下状态。

Components 的价格格式可用明确标注“虚构格式示例”的测试值，不能挂在真实产品上冒充官方报价；Screens 如使用真实商品则必须有官方出处，否则不显示价格。所有示例都显示统一示例提示，不与真实新闻运行混同。

### 7.3 Patterns 与宽屏

- 顶部栏、统一底栏、吸顶筛选、分组标题和卡片容器来自同一套组件。
- 吸顶区域采用不透明surface和清楚边界，内容区预留其高度；锚点滚动有scroll-margin，Tab聚焦不能落在遮挡区。
- 好玩/好买手机固定两列，平板三列、宽屏四列，居中最大1200px；是双列体验的响应式延伸，不把桌面强行挤成720px。若阿欢要求所有宽度都只两列，应在Playground评审时改为最大960px两列方案。
- 瀑布流保留数据和DOM顺序；不采用CSS多栏造成“左列到底才读右列”，也不使用dense回填打乱排序。拟采用CSS Grid细行跨度，按图片宽高比预留，再在图片/字体就绪时测量修正；无JS退化为可读双列网格。
- 同一组内连续铺卡，组间标题明确；切换筛选返回列表起点，收藏或展开卡片不无故重排已阅读位置。以来源图片为主，裁切不能丢掉书封、作品名或产品要点。

### 7.4 Screens

五页以393×852作为主要手机评审尺寸，可点击底栏切换，支持页面滚动、筛选、搜索、折叠、看图/详情、收藏、撤销和返回；好看额外评审三种顶部模式。不得只做五张静态画板。

今日保持杂志式节奏，三个块的卡片分别使用资讯与图片组件。收藏按时间混排，复用三种卡片，类型标记可见；不以类型切段。浅深主题和两档密度均能切换，主题/密度切换不清空收藏示例或筛选。

Playground 独立存储命名空间，与正式站公开/内网收藏隔离；示例动作不调用生产接口、不触发采集、工作流、发布或购买。采用现有公开样本或明确虚构样本，不读取真实私有数据；不会沿用旧prototype-v05页面当新交付。
