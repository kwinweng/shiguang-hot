# 官方网站新闻：中文优先发布

## 约束

- 范围是频道配置中 `type: feed/page` 的新闻，不改变 Telegram、博主或热搜口径。不改定时任务、密钥、翻译模型或用量限制。生产翻译沿用获批的 DeepSeek Flash；Mac 发布器本身只读回填缓存，不会调用模型。
- 有可展示的中文标题和摘要（原文没摘要可为空）才进频道、轮播、折叠、深链索引和搜索。原生中文可直接用；中文标题配英文摘要不算已就绪。GitHub 仓库名 `owner/repo` 保留，介绍仍执行中文规则。
- 全文未就绪时只显示中文摘要和提示。英文原文只在主动操作「看原文」或「打开原文」时查看。可疑的全文/结构化译文不采用，不以原文补位。汉字与拉丁词检查是保守门槛，不是译文质量证明；术语较多可能被暂扣。
- 拦截在发布投影，不从采集输入删除条目；旧归档重建搜索时也验证当前版本，不回退旧英文快照。浏览器旧数据和旧收藏用同一规则检查，不删除用户收藏；未就绪的旧收藏只显示中文提示。已经加载的旧站代码须刷新切到新版本，不能追溯删除已公开的历史 Git 对象或浏览器缓存。

## 为什么会直接上英文

现有 Mac 发布任务调用 `rebang_refresh.sh`，入库查译文缓存，未命中只进入待译队列。原来的建站不检查译文是否齐，搜索又会扫一遍历史归档。条目缓存还会把「只有标题」当成已经填好，或用全文截断冒充指定摘要的译文。发布端、归档搜索和浏览器旧数据入口现在验证 `translation.summary_source` 是否与原摘要一致；没有这一来源标记的旧译稿须经过回填。共享段落缓存命中明显不合格的译文时，另排一次修补，不覆盖旧缓存，也不反复排队；没有可用译文的条目继续暂扣。Mac 发布器不调用模型。

## 离线验收

- 未译、只有标题、错误英文回显、旧归档：不出现在公开轮播、频道页、折叠、深链索引及搜索；原输入或旧归档未删除。
- 中文标题 + 英文摘要继续排队；晚到的中文缓存可以补齐。原生中文正常；仅链接不是正文语种依据。
- 中文标题/摘要已齐但正文未齐：深链显示中文摘要；正文在默认视图不可见，主动展开可看原文。译文纯文本有效但译文块未就绪时不能落到英文块。
- 旧搜索/收藏快照不回退到原始英文标题或摘要。搜索可用原文关键词命中合格条目，但结果仍展示中文。

不手动触发生产；上线前需确认已有 Flash 回填能处理 Mac 的待译队列，发布器会自动读取回填但不会替它翻译。部署后核对 `source_commit`，再查有代表性的英文源、搜索和深链的实际效果。
