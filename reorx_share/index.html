Reorx’s ForgeAI11-13 11:03

vibench 快做好了

我想做一个用户调查，因此在这里正式介绍一下这个项目。之前零零碎碎发过一些开发日志，但一直没有系统地讲过它到底是干什么的。 我对它的定义是一个 Agent Orchestrator，这是它的工具性质。但它实际的使用场景是成为我日常调度 agent 的工作台，因为我目前的所有工作几乎都是用 Agent 来完成的。说到这里，我想提到一点，我觉得我们这些程序员和开发者已经基本完成了从“机械师”到“驾驶员”的转变。我们的不再是趴在摆满扳手锤子等零散工具的桌子上手动打磨，而是坐在现代化驾驶舱内，借助仪表盘和操作杆，最大化发挥机魂的性能。从这个意象上来说，vibench 就是我想为自己打造的车机。当然我也认为它可以适合其他人使用，因为我实在觉得目前的工具都没有它好用。 Herdr 这种新的多路复用器算是目前用的较多的一类，但还远远不够。因为它仍然以 Session 为信息的交互界面，在 Session 之上没有任何抽象。用户还是要面对大量的原始文字结构，带来很高的心智负担，限制了并行开发的效能。 回到 vibench，它是我在原始 Agent Session 调用与项目管理工具之间找到一个平衡点。具体包含以下两个核心方面： 1. 统一需求输入口 不论是我此时有一些临时的新想法想要记下来晚点做，还是我现在立刻就有东西要执行和开发，我都希望它们走同一个地方去记录。我可以将所有的 Issue 分门别类地放好，用不同的维度进行过滤和查询。我希望从项目管理的层面统一开发开发任务的起始点。 2. 聚焦关键信息与结构化展示 在开发过程中，我希望有一个地方能够只看到我最需要关注的那些东西。并且当我点开每一个需要关注的对象时，都能看到最重要的信息，即 Agent 的最终返回结果，以及从中提取出来的内容。例如： - 需要我审阅的规划 Plan 或 Spec - 提交上来的设计稿 - 验收的证据 这些信息会在一个更加合理的结构化界面上展示和使用。 这两件事一直是我使用终端 agent 最大的痛点。而如今被解决了，因为 vibench 实现了对无用信息和噪音信息的过滤，以及对有效信息的提取和结构化。这就是它为我带来最大的价值。 由于 vibench 被设计为尽可能与 Agent 解耦，并且不自己造 harness 的轮子，从而可以叠加在用户已有的工具之上，而不是替代它们。目前因为我个人的需求，我只接了 claude code 还有 codex，在正式发布前，我准备再加一个大家用得比较多的成为第三种支持的 agent。现在我想问一下大家：你平时主要使用哪一个 Agent 工作呢？评论区回答，或者说说你的其他看法。

我突然意识到一件事情

比方说现在 Claude Code 之类的这种 agent harness 其实也有很多可定制的功能，比如 mod，还有一些像 PI 和 DSH 这样自定义程度非常高的 harness。但是我发现现在我自己几乎不怎么去调整。如果真的遇到有什么问题需要去弄的话，也是很短的时间让 agent 自己去搞定了。 说白了，现在折腾工具给我带来的乐趣，远没有让 agent 多跑一会儿、把额度利用得更充分对我来说更有吸引力。但以前不是这样。以前在用 IDE 的时代，我可以花一整天的时间折腾 Vim 的配置、VS Code 的插件等等这些东西。 这让我思考为什么有这种差别呢？是我变了吗？我感觉自己并没有变，我还是乐意去给我现在的工作流添砖加瓦，只不过他们不再需要我自己动手，很多时候一句话让 agent 就做好了。我想真正的原因是：在以前那个一天可能只能开发一个功能的时代，人的注意力很容易被分散，写代码是一种平和的快乐。所以在这种平和的快乐之中，我很容易会想通过折腾生产力工具来得到新的刺激。但是在 AI Coding 的时代，使用 agent 本身就是最大的刺激了，且阈值被提高，折腾工具再也不能像以前那样让我满足了。
